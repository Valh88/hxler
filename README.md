# Hxler

Write Erlang/Elixir NIFs in [Haxe](https://haxe.org) (C++ target) with a
[rustler](https://github.com/rusterlium/rustler)-style API.

`hxler` is a "mini-rustler": the Haxe side provides `hxler.core` (a typed
`Env`/`Term`/`Atom`/`Binary`/`ResourceArc` API over `enif_*`), and the Elixir
side compiles your Haxe code and loads the resulting NIF — no manual glue.

Supports: plain types, strings/lists/maps/tuples, `Option`/`Result` errors,
ETF round-trips, dirty schedulers (`dirty_cpu`/`dirty_io`), panic trapping
(Haxe exceptions become `:nif_panicked`), resources (native state between
calls), owned envs + pids, refs.

Platforms: Windows-first (MSVC; mingw fallback), cross-platform by design
(Linux uses the same architecture). OTP 27+, Elixir 1.19+, Haxe 4.3.x.

## Installation

```elixir
def deps do
  [
    {:hxler, "~> 0.1.0"}
  ]
end
```

The Haxe SDK ships inside the `hxler` package — no separate `haxelib` install
is needed. `use Hxler` locates it automatically (`deps/hxler/hxler/source` for
hex deps, the configured `path:` for local ones).

You need `haxe` (with hxcpp: `haxelib install hxcpp`) on your PATH, plus a
C++ toolchain (MSVC on Windows).

## Quick start

### 1. Scaffold the NIF

```sh
mix hxler.gen my_nif --module Example.MyNif
```

This creates `native/my_nif/` with a Haxe package `my_nif`:

- `source/my_nif/MyNifNif.hx` — the NIF class (`@:nif` functions)
- `source/my_nif/Entry.hx` — generated glue (function table, `ERL_NIF_INIT`)
- `source/my_nif/Main.hx` — dummy main for the DLL build
- `build.hxml` — the Haxe build

### 2. Write the NIF

`native/my_nif/source/my_nif/MyNifNif.hx`:

```haxe
package my_nif;

import hxler.core.Env;
import hxler.core.NifResult;

@:keep
@:headerCode('#include "erl_nif.h"')
@:build(hxler.macros.NifBuilder.build())
class MyNifNif {
    @:nif
    public static function add(a:Int, b:Int):Int {
        return a + b;
    }

    @:nif
    public static function greet(name:String):String {
        return "Hello, " + name + "!";
    }
}
```

Every `@:nif` static function becomes a NIF. The wrapper (argument decoding
by signature), the `ErlNifFunc` table and `ERL_NIF_INIT` are generated by the
macros.

### 3. Load it from Elixir

```elixir
defmodule Example.MyNif do
  use Hxler, otp_app: :example, nif: :my_nif

  # stubs: one per @:nif, names are snake_case (camelCase is converted)
  def add(_a, _b), do: :erlang.nif_error(:nif_not_loaded)
  def greet(_name), do: :erlang.nif_error(:nif_not_loaded)
end
```

`use Hxler` compiles the Haxe NIF at compile time (with a stale-check, so
unchanged sources are not rebuilt), copies the artifact to
`priv/native/<nif>.dll|.so` and installs an `@on_load` hook that calls
`:erlang.load_nif`.

### 4. Test

```elixir
test "add" do
  assert Example.MyNif.add(20, 22) == 42
end

test "greet" do
  assert Example.MyNif.greet("hxler") == "Hello, hxler!"
end
```

```sh
mix test
```

A full consumer example lives in [`example/`](example/) (path dependency).

## The NIF API

Argument and return types supported in `@:nif` signatures: `Int`, `Float`,
`Bool`, `String`, `Atom`, `Term`, `haxe.Int64`, `cpp.UInt64`, `Null<T>`,
`Array<T>`, `Map<K, V>` (returned as key/value pair tuples), `hxler.core.ResourceArc<T>`,
plus custom types with static `hxEncode`/`hxDecode`.

Errors follow rustler semantics: return `NifResult<T>` (`Ok(v)` /
`Error(BadArg)`, `Error(Atom("zero_division"))`...) to produce
`{:error, reason}`; a naked `Term` result is returned as-is; Haxe exceptions
are trapped and surface as `:nif_panicked`.

```haxe
@:nif
public static function safeDiv(a:Int, b:Int):NifResult<Int> {
    if (b == 0) return NifResult.Error(NifError.Atom("zero_division"));
    return NifResult.Ok(untyped __cpp__("{0} / {1}", a, b));
}
```

```elixir
Example.MyNif.safe_div(10, 2)  # => 5
Example.MyNif.safe_div(10, 0)  # => {:error, :zero_division}
```

### Dirty schedulers

```haxe
@:nif(schedule = "dirty_cpu")
public static function fib(n:cpp.Int64):cpp.Int64 { ... }
```

### Raw NIFs

Skip the wrapper and take `(env, argc, argv)` directly (requires
`@:nif(arity = N)`):

```haxe
@:nif(arity = 1)
public static function atomText(env:Env, _argc:Int, argv:cpp.Pointer<hxler.nif.raw.NifTerm>):hxler.nif.raw.NifTerm {
    ...
}
```

### Resources: native state between calls

```haxe
class Accum implements hxler.core.Resource {
    public var items:Array<Int> = [];
    public function new() {}
    public function push(v:Int):Void items.push(v);
}

@:nif
public static function accumNew():hxler.core.ResourceArc<Accum> {
    return hxler.core.ResourceArc.make(new Accum());
}

@:nif
public static function accumPush(arc:hxler.core.ResourceArc<Accum>, v:Int):Void {
    arc.get().push(v);
}
```

```elixir
acc = Example.MyNif.accum_new()
Example.MyNif.accum_push(acc, 1)
Example.MyNif.accum_sum(acc)  # => 1
```

Resources must be registered in a load callback
(`--with-resources` in `mix hxler.gen` scaffolds this; see `native/math/`
for a full example).

### Owned envs and pids

```haxe
var owned = new hxler.core.OwnedEnv();
var pid = hxler.core.Pid.self(env);
pid.send(env, hxler.core.AtomCache.intern("hi").toTerm(owned.env()));
owned.dispose();
```

## How compilation works

`use Hxler, otp_app: :my_app, nif: :my_nif` (compile time):

1. stale-check: skip if `priv/native/<nif>.dll|.so` is newer than every
   `.hx` source and `build.hxml`;
2. run `haxe native/<nif>/build.hxml` (injecting `-D hxler_erts_include`
   from your OTP install and the SDK classpath/include), then
   `haxelib run hxcpp` to produce the DLL/SO;
3. copy the artifact to `priv/native/<nif>.<ext>` (deleting the old file
   first — overwriting a loaded NIF segfaults the VM);
4. `@on_load` → `:code.purge(__MODULE__)` + `:erlang.load_nif` (no
   hot-upgrade).

Each `@:nif` function must have a stub in the Elixir module **before**
`load_nif`, otherwise the load fails with
`{:bad_lib, "Function not found ..."}`. Stub names are snake_case
(`accumPush` → `accum_push`); explicit `env` first parameters do not count
towards arity.

## Tests

- `mix test` — E2E ExUnit suite (arithmetic, strings/lists/maps, option/
  result, resources + dtor, dirty_cpu, refs, pids, parallel stress).
- `hxler/test.hxml` — Haxe-side utest suite (ABI constants, wrappers).
- `hxler/check.hxml` — compile-time ABI verification of all raw `enif_*`
  wrappers against the real ERTS headers.
